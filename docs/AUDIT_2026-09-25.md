# Audit, 2026-09-25 (overnight)

Three read-only reviews checked core Customize, core app/tabs/gl and the three game plugins.
Together they reported about 50 candidate defects. Each one was **re-traced by hand before
anything changed**. A fix that has a test was checked in the container; where practical, the test
was also run against the old code to show it fails there ("mutation-verified").

Container state at the end:

- 148 `shell_check` assertions, all passing (168 after 2e-2 was built later the same night). The whole of `shell_check` passed 10 of 10 runs
  under full CPU load, after the thumbnail pool fix and before the last few tests were added.
- The POE2 adapter's 3 new checks pass.
- `run_tests.sh` passes all suites, and `verify-src.py` is clean.
- Nothing here has run on MSVC yet. **The next `Run Everything.bat` is the first Windows build.**

## Fixed — checks that could not fail, runs that could hang

- **C5:** `poe2_dump`'s needle matched the failure line. Success now logs `dump: wrote`, failure logs `dump: FAILED`.
- **C12:** the `models: ` / `textures: ` needles matched "0 row(s)". An unknown `--show-tab` id only warned. **`fox_customize` passed on "built 0 part(s)"** and `fox_files` on a startup line; both appear in every FOX launch before any index. The needles are now non-zero regexes, `shell: shown <tab>`, and a character built with at least one part.
- **C6:** `--quit-when-ready` **hung forever on an index failure**. It now logs `shell: index FAILED` and exits with code 2 (tested with a corrupt POE2 index). A **harness watchdog** thread ends any harness run after `--harness-timeout` s (default 1800) with exit code 4. FOX with 0 archives now fails instead of reporting ready.
- **G10:** `--build-roundtrip` said "same" for an empty or failed apply. **G11:** `--clip` said decoded when it wasn't.

## The workflow, reviewed

`Run Everything.bat` took about 7 minutes (run 14). FOX was 12 launches of about 18 s each, and 6
of them looked for lines a single boot writes; POE2 had 4 more like that.
`Build and Verify.bat` now has `:launch` (run once into `_<name>.log`) and `:expect` (a check
reading that log; a `re:` needle is a findstr regex).

| Launch | Checks it serves |
|---|---|
| POE2 `poe2_shell` (`--show-tab models,textures,customize,bulk`) | boot, models, textures, customize, bulk |
| POE2 `poe2_build` | build, socket |
| FOX `fox_shell` (`--show-tab models,textures,customize,files`) | boot, models, textures, files, catalogues |
| FOX `fox_character` | shot_character, customize |
| D4 `d4_rig` | boot, shot_rig |

With the two new crash checks the bat ran 42 checks; 2e-2's `fox_core_customize`, added after the
audit, makes 43. The run should still be roughly 2 minutes shorter than run 14. **None of this has run under cmd yet:** the helpers copy the proven `:check`/`:checkany`
patterns, and the file is CRLF with no `::` inside a block.

Also in the workflow:

- `Run Everything.bat` and `Launch D4 with multiseg.bat` are now mirrored in the container repo.
- `Launch D4 with multiseg.bat` is obsolete: D4 loads multi-segment sub-objects by default since
  2026-09-23. It's left for you to delete.
